# paper/ — the LOAM paper's benchmark numbers, frozen

This directory holds the gLMBench results reported in the LOAM manuscript, as the records they
were read from. Nothing in it is written by a benchmark run: your own runs go to `results/`.
Use it to check a run of yours against the paper
([docs/REPRODUCING_THE_PAPER.md](../docs/REPRODUCING_THE_PAPER.md)):

```bash
python scripts/compare_to_paper.py results/loam_paper/glmb_<hash>.json
```

| File | What it is |
|---|---|
| `records/glmb_*.json` | The 13 records behind the paper's benchmark figures and tables: 4 LOAM models and 9 comparators, each with the five `loam_paper` task rows. Sanitized (below). |
| `records/SOURCES.sha256` | For each sanitized record, the sha256 of the original it was made from. |
| `public_route/glmb_*.json` | The four LOAM rows re-scored from the released weights (`Soilytix/LOAM-*`) through the public `loam-hf` adapter. |
| `models.csv` | One row per model: public id, measured parameter count, adapter, spec, paper hash and record, public-route hash and record, Hub repo, source checkpoint. |
| `reference_scores.csv` | Every metric of every record in one long table: every tap of both layer sweeps, every RNAGym assay. Generated by `scripts/build_reference_table.py`. |
| `LEADERBOARD.md` | The five rows as a leaderboard, rendered from the records by the same script. |
| `kmer_floor.json` | The model-free k-mer floor of each task: the score a k-mer frequency vector gets from the unmodified task code, for k = 1…6. Produced by `python scripts/kmer_floor.py` from this repository (CPU, a few minutes); every run is bitwise equal to the floor the paper reports. |

`reference_scores.csv` and `LEADERBOARD.md` are generated, never edited by hand:
`tests/unit/test_paper_reference.py` regenerates them and requires them to be byte-identical.

## How to read a record

A record is keyed by its **model hash**, `glmb:sha256(weights digest ‖ hashed config ‖
adapter@version)`. Two runs of the same weights through the same adapter and serving
settings get the same hash; anything that could change the numbers gets a new one. Each task
row holds `status`, `primary_metric` (the headline), `metrics` and `metadata`. In the two
sweep rows, `layer_<i>_<metric>` is the score at tap `i`, and `best_layer` is the argmax
over taps after degenerate taps are excluded (`metadata.best_layer_selection`). The best tap
is chosen on the test split, so it is a retrospective upper bound; the paper reports it next
to the last-layer value (the single-layer rows).

## The LOAM rows: two routes to the same numbers

The paper scored the LOAM checkpoints with the training codebase's own model implementation
(the records' `loam` adapter, `adapter_version` 0.3.0), which is not part of this repository.
The released weights are those same checkpoints, exported to the Hugging Face format;
`models.csv` names the checkpoint each came from. This repository serves them through
`loam-hf`, which reproduces the native arithmetic (fp32 load then bf16, BOS prefix, the same
batching, bf16 mean pooling, fp32 log-softmax).

Scored that way in the reference environment (torch 2.12.0+cu126, transformers 5.12.1,
`envs/constraints-paper.txt`), each LOAM model reproduces its paper record **bitwise**
on every metric of all five rows (416 of 416 metrics over the four models): `public_route/` holds those runs, and
`test_paper_reference.py` checks them with `compare_to_paper.py --exact`. Their model hashes
differ from the paper's by construction (a different adapter, and a digest of the weight file
rather than of a training checkpoint), which is why `models.csv` keys the comparison by model
id.

## What sanitizing changed

The originals carry the paths and host of the machine they ran on. The export rewrote only
these fields, by script, and left every score, count and metadata value as recorded:

- `provenance.host`, every `python_exe` and `gpus` field, and the unused container `image` of
  one spec: `"<redacted>"`. Wall-clock timing fields (`embed_seconds`,
  `embed_seconds_per_window`, and `seconds` in `kmer_floor.json`) were removed.
- LOAM records: the local checkpoint path became the Hub repo id (`Soilytix/LOAM-*`); the
  training-config path and the digest-cache path became `"<redacted>"`.
- `model_spec.display_name` became the public model id (`LOAM-624M`, ...).
- `readout_note` (prose the adapter writes) was replaced where the original cited files,
  documents or tasks that are not in this repository: by the public adapter's note, or, for
  the LOAM records (whose native adapter is not public), by a note describing the same
  readout. Likewise, the essentiality rows' `metadata.probe` label lost a reference to an
  internal document section.
- `tasks` was trimmed to the five rows the paper reports. The originals were scored under a
  larger internal benchmark (hence `"benchmark": {"name": "full"}`), whose other rows the paper
  does not use.

The model hashes are unchanged, and `SOURCES.sha256` links each file to the exact original the
manuscript's figures were built from.
